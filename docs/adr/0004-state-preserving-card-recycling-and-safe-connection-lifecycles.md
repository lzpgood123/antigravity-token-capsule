# ADR 0004: 状态感知卡片复用与连接生命周期安全 (State-Preserving Card Recycling & Safe Connection Lifecycles)

## Status

Accepted

## Context

在 `v1.1.0` 发布后，随着长耗时任务与多层级 Subagent 并发运行，我们在高频遥测轮询（500ms~1000ms）中观察到两个关键体验缺陷：
1. **列表闪烁与折叠态丢失**：在 `update_data` 时直接调用 `clear_subagent_cards()` 销毁全部子卡片并重新实例化，不仅造成高频微闪烁，而且重置了用户手动展开的手风琴子任务面板；
2. **SQLite WAL 连接句柄残留**：在解析高并发写入的 `db-wal` 文件时，若并发锁冲突或异常提前退出，未被显式关闭的 SQLite 连接会导致文件句柄残留。

## Decision

我们确立了 **状态感知卡片就地增量复用 (In-Place UI Recycling)** 与 **防御性连接生命周期保障** 架构：

1. **就地增量复用 (In-Place Recycling)**：
   * 在卡片容器管理中引入基于子智能体 `id` 的实例复用池。
   * 轮询刷新时比对已有卡片列表：已存在的卡片仅调用其增量更新方法（更新耗时、Token 变化、指示器颜色），新增的卡片动态追加，已移除的卡片安全解绑释放。
   * 保证用户手动点击展开的手风琴和派生分支树在任何数据刷新期间保持 100% 连续性与零闪烁。
2. **强制 `try...finally` 零泄漏保障**：
   * 在 `data_engine.py` 中对所有 SQLite 连接实施严格的 `try...finally` 析构闭环，杜绝任何中间异常引发的连接残留。
3. **启动默认强制紧凑单卡 (Compact Tabbed Mode)**：
   * 在窗口初始化与偏好加载逻辑中，强化默认紧凑单卡（320px）的约束，避免极端布局计算偏差导致意外全展开。

## Consequences

- **Positive**：
  * **零抖动渲染**：重绘时消除控件反复重构的 CPU/GPU 峰值抖动，列表操作流畅度大幅提升。
  * **交互状态完全持久**：用户正在查看的 L1/L2 手风琴卡片不会因后台 Agent 产生新日志而被强制折叠。
  * **资源绝对安全**：彻底杜绝 WAL 锁争用导致的文件占用与连接泄漏。
- **Trade-offs**：
  * 卡片更新逻辑增加了差异比对与就地更新代码分支，复杂度略高于简单的“清空重建”。
